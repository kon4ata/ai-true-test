## AI-TRUE

**Стек**: NestJS, Next.js, PostgreSQL

**Реализовано**:

1. Модуль работы с отзывами (доп. задание А)
2. Сервер с API, миграциями и сидированием
3. ЛК для работы с метриками и отзывами
4. 2 автоматизированных теста для изоляции данных и получения статистики и отзывов

**Тестовые пользователи** (вымышленные):

* `admin@example.com` / `admin123` - админ, видит все компании
* `client1@example.com` / `client123` - клиент "Кофейня Зерно"
* `client2@example.com` / `client123` - клиент "Автосервис Мотор"

### Запуск локально

- создать файл .env в backend и frontend и скопировать настройки из .env.example

`docker compose up -d` - для запуска БД (пока что только БД)

`npm run db:migrate` - для запуска скрипта миграции

`npm run db:seed` - для запуска скрипта сидирования

`npm run test:e2e` - для запуска тестов

### Запуск в проде через Docker

`docker compose up -d` - запускает бэк, фронт и БД

### Допущения

1. Нет нормального дизайна на фронте
2. В некоторых местах есть костыли (миграции в базу из докера сделаны через отдельный скрипт и файл migrate.ts)
3. На фронте присутствует мерцание UI при переходе на /
4. Не реализовано обновление токенов через refresh-токен. Отзыв токена возможен только через удаление пользователя. Для простоты реализации оставил один долгоживущий токен

### Масштабирование

1. Добавить кэширование через redis для статистики
2. Решить вопрос с получением отзывов через offset. На большом массиве отзывов будет заметная просадка в производительности. Как вариант, попробовать использовать курсорную пагинацию
3. Добавить реальные индексы к запросам чтения
4. Добавить rate-limit к API
